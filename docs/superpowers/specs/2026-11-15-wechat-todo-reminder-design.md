# 微信待办备忘录与定时提醒小程序设计文档

- **创建日期**：2026-11-15
- **方案类型**：方案 1（微信云开发 + PushPlus 微信卡片推送）
- **适用场景**：个人 / 亲友小圈子自用高效待办提醒

---

## 1. 核心意图与背景 (Intent & Why)
解决个人日常待办管理的“遗忘”痛点：
1. **被动晨间唤醒**：每天早晨醒来在微信中直接收到一条待办晨报卡片，清晰呈现今天要做什么、有哪些已逾期，无需专门打开小程序。
2. **临期强提醒**：为每一项重要待办单独定制提前提醒窗口（如 15分钟 / 30分钟 / 1小时 / 1天），在 DDL 到来前准时收到微信卡片警报。
3. **绕开审核门槛**：微信对个人开发者限制了长期订阅消息权限，通过 PushPlus 免费服务号通道实现无需每次手动点授权的 100% 稳定微信直达。

---

## 2. 目标、非目标与反面目标 (Goals, Non-Goals, Anti-Goals)

### 2.1 目标 (Goals)
1. **轻量待办管理**：快速录入、编辑、删除待办，支持截止日期时间（精确到分钟）与单独的“提前提醒时间”设置。
2. **自动化早间晨报**：每天早晨定时（默认 08:30，可自定义）聚合未完成任务并发送微信图文卡片。
3. **精准 DDL 预警**：云端定时器每 5 分钟巡检一次，到达每项任务的预警时间点后自动发送临期微信通知，已提醒的任务自动标记防重发。
4. **小圈子多用户隔离**：基于微信 OpenID 实现天然数据隔离，每个使用者可配置自己的 PushPlus Token，各收各的提醒。

### 2.2 非目标 (Non-Goals)
- 不做多用户协同指派、团队甘特图、复杂看板；
- 不做社交分享、公开社区广场；
- 不接入付费短信或需要企业营业执照的微信服务号认证。

### 2.3 反面目标 (Anti-Goals)
- **杜绝频繁弹窗打扰**：不依赖每次保存待办都强制唤起微信订阅授权弹窗；
- **杜绝复杂运维**：不购买自建服务器、不配置公网域名、不维护 Nginx/SSL 证书，全部依托微信云开发（CloudBase）免运维。

---

## 3. 技术路线与对比决策 (Approaches)

- **方案 1（选用）：微信云开发 + PushPlus 微信推送**
  - *权衡*：零服务器成本，真正推送到微信聊天列表，支持富文本排版。唯一前置动作为用户在设置页填入个人 PushPlus Token（关注公众号一键获取）。
- **方案 2（备选）：纯前端离线 + 手机系统日历 (wx.addPhoneCalendar)**
  - *权衡*：无需网络与云函数，但提醒落在系统日历/锁屏中，不能直接在微信服务通知中汇总查看。
- **方案 3（备选）：官方企业认证服务号模板消息**
  - *权衡*：正规商业路径，但需要企业营业执照和每年 300 元认证成本，对个人自用太重。

## 4. 架构与数据模型 (Architecture & Data Model)

### 4.1 云数据库集合 (Cloud Database Collections)

#### 集合 1：users（用户配置表）
- `_id`: 记录唯一 ID
- `_openid`: 用户的微信 OpenID（云开发系统自动注入并权限隔离）
- `pushplus_token`: 字符串，用户的 PushPlus 个人 Token
- `morning_report_enabled`: 布尔值，晨报开关（默认 true）
- `morning_report_time`: 字符串，每日晨报时间（默认 '08:30'）
- `updated_at`: 时间戳

#### 集合 2：todos（待办事项表）
- `_id`: 待办唯一 ID
- `_openid`: 用户 OpenID
- `title`: 字符串，待办标题（必填）
- `desc`: 字符串，详细备注（选填）
- `ddl`: 时间戳，截止时间
- `remind_offset_minutes`: 数字，提前多少分钟提醒（0=准时, 15, 30, 60, 120, 1440）
- `target_remind_time`: 时间戳，计算得出的提醒触发时间点（ddl - offset）
- `status`: 字符串，'pending'（进行中）或 'done'（已完成）
- `has_reminded`: 布尔值，该待办是否已发送过 DDL 预警提醒
- `created_at`: 时间戳
- `updated_at`: 时间戳

## 5. 云函数与调度引擎 (Cloud Functions)

### 5.1 cronDailyMorning（每日晨报巡检）
- **触发频率**：Cron 触发器，每日固定时间运行（如每天早上 08:30）。
- **业务逻辑**：
  1. 扫描 users 集合中开启晨报且配有有效 pushplus_token 的用户；
  2. 针对每个用户，查询 todos 中其名下所有 status == 'pending' 的待办；
  3. 按照任务紧急度分为：【已逾期】、【今日待办】、【后续事项】；
  4. 渲染 Markdown 待办晨报卡片，调用 PushPlus 发送至微信。

### 5.2 cronCheckDdl（DDL 提前预警巡检）
- **触发频率**：Cron 触发器，每 5 分钟执行一次。
- **业务逻辑**：
  1. 获取当前时间戳 now；
  2. 查询 todos 集合中满足 status == 'pending' 且 has_reminded == false 且 target_remind_time <= now 的任务；
  3. 读取对应用户的 pushplus_token，发送微信临期报警卡片；
  4. 标记 has_reminded = true 防止重复提醒。

### 5.3 todoApi / userApi
- 供小程序前端调用，处理待办的增删改查、状态勾选、Token 录入与一键测试推送连通性校验。

## 6. 小程序前端页面与交互流程 (Frontend UX & Flow)

### 6.1 页面划分
1. **主页（待办列表页）**
   - 顶部统计卡片：待办总数、今日待办数、已逾期数；
   - 分类 Tab 切换：【今日待办】/【全部待办】/【已完成】；
   - 待办项卡片：点击复选框即标记完成/未完成；长按或侧滑删除；点击进入编辑；
   - 悬浮添加按钮（+）：打开新增待办面板。
2. **待办新增/编辑弹窗/页**
   - 标题输入（必填，字数限制 50 字）；
   - 截止日期与时间选择器（Picker）；
   - 提前提醒单选 Picker（准时 / 提前 15 分钟 / 提前 30 分钟 / 提前 1 小时 / 提前 2 小时 / 提前 1 天）；
   - 备注输入框。
3. **个人设置页**
   - PushPlus Token 录入与一键“发送测试消息”验证连接状态；
   - 每日晨报开关与时间选择（默认 08:30）；
   - 极简使用指南（1 分钟关注公众号获取 Token）。

---

## 7. 异常处理与边界情况 (Edge Cases & Failure Modes)

1. **Token 未配置或失效**：若用户未填 Token 或接口调用失败，云函数记录日志并安全跳过，前端提供一键自测工具。
2. **任务已提前完成**：若用户在提醒时间前把待办标为 done，cronCheckDdl 过滤掉不推送。
3. **修改 DDL**：用户重新修改截止时间后，系统自动重新计算 target_remind_time 并重置 has_reminded = false。
4. **时区一致性**：所有时间计算统一使用东八区（Asia/Shanghai，UTC+8）。
